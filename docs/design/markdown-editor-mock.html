Design proposal, 2 November 2026. Nothing here is built. Engine read at fluent-gpu de5e6b24f.

Keep the file as the document, and hide the syntax while people write.

Build MarkdownEditor as a projection over the source text. The buffer holds the file's exact characters, the renderer conceals the markers, and every edit is one replace on that text. No tree is ever written back, so nothing the person did not touch can change.

Markers never appear when the caret arrives, because that reflows text on a caret move and breaks the no-layout-jumps rule. Raw source is one key away (Ctrl+/) at the same offset. The first version covers text, lists, tasks, inline marks, the selection flyout and undo. Tables, code and images start as safe islands.

High risk: caret, selection and IME across many text flows have not been done on this engine. A short spike comes first, and there is a lower-risk plan B if it fails.

Worth trying by hand

  • Type **word**, then keep typing: the text after the closer is plain. Ctrl+Z once takes back only the closer.
  • Select across a paragraph and a list, then press Ctrl+B or delete. The file stays balanced.
  • Click the task boxes. One character changes in the file.
  • Click a table. Enter opens only that block's source.
  • Switch markers to Reveal and arrow through the first paragraph. The lines below jump. That is the case against it.

What the mock is not

  • It is browser text, not the engine. Nothing here was run on FluentGpu.
  • Its parser is about 100 lines and far looser than MarkdownParser.
  • Block changes snap here. The engine would ease heights (see the no-jump table).
  • Newlines are LF only here. The proposal keeps CRLF and mixed endings.
  • IME goes through a browser textarea, which says little about the engine's IME path.

Markers

Hidden in the rendered view, and the caret never reveals them. Raw source is the way to see them.

A reveal changes line widths when the caret merely moves, so wrapped lines and everything below shift. At 460 px that happens often. RichEditBox, the WinUI reference, also shows only formatted text.

checked owner rule in MEMORY.md "No layout jumps". inference reflow cost, try the toggle above. Owner decision 1.

Typed Markdown

** * ` ~~ == and line starts # - 1. > - [ ] --- ``` take effect when the construct is complete. An opener with no closer stays visible and dimmed while the caret is after it. The file holds what was typed, so there is no conversion step that can guess wrong. Ctrl+Z removes only the closing delimiter.

checked Milkdown input rules (preset-commonmark/src/mark/strong.ts), undo seal semantics in TextUndoStack. web Notion's typed shortcuts, via third-party guides.

Shortcuts

Ctrl+B, I, E (code), Shift+X (strike), Shift+H (highlight), K (link), L (task), 0 to 6 (block), / (source). Ctrl+U does nothing and says why: Markdown has no underline, so the WinUI Underline button is replaced.

checked TextCommandBarFlyout.cpp:306-314, TextEditKeymap.Map (Alt and Win stay out of editor chords). memory Ctrl+/ for source is Typora's key.

Selection flyout

WinUI's CommandBarFlyout shape, placed top edge left over the selection. Primary row: Bold, Italic, Strikethrough, Code, Highlight, Link, then More for block styles. Opens after a mouse, pen or touch selection and never after a keyboard selection. It does not take focus, and with a mouse it closes when the pointer moves away. Checked primary commands use the accent pill.

Cut, Copy and Paste live in the overflow for a mouse and in the primary row for touch or pen, as WinUI does. Right click or Shift+F10 opens the context flyout expanded.

checked TextBoxBase.cpp:5382-5411, Common_themeresources.xaml:49-50, TextCommandBarFlyout.cpp:297-319, CommandBarFlyout_themeresources.xaml:24-30,107.

Insert menu

/ at the start of an empty line opens a filtered list. Enter replaces /query with the block's syntax in one undo step. Escape leaves /query as text, so typing paths stays safe. The footer Insert button is the same menu for people who never learn /.

checked Crepe's slash menu groups (crepe/src/feature/block-edit/menu/config.ts:61-344), WinUI menu row metrics (MenuFlyout_themeresources.xaml:255-261). web Notion's slash menu.

Links

A plain click puts the caret in the text and opens a small card: address, Open, Remove. Ctrl+click follows through OnLinkClicked, or the existing warning dialog. The link text edits in place. A reference link keeps its definition line, and the card says where the address lives. A pasted URL over a selection becomes a link.

checked markdown.md §6.1. web Typora's export turns reference links into inline links, which this avoids.

[[wikilink]]

The engine knows only "a consumer inline syntax plus a completion source". Typing the trigger opens an AutoSuggest-style list from the consumer. Accepted, it writes [[Name]]. The whole link is one caret stop: arrows jump it, Backspace selects it first. An alias ([[Name|label]]) shows the label and is never rewritten.

checked MarkdownInlineSyntax, MarkdownLink.Syntax. inference new MarkdownCompletionSource seam.

Task lists

Clicking the box changes one character at MarkerOffset, with no layout change since the box is the same size in both states. Enter continues with the sibling's bullet and an empty box. Enter on an empty item leaves the list.

checked MarkdownTasks.Toggle, markdown.md §5.6, §6.4; continuation shape in lang-markdown/src/commands.ts:98,238.

Tables

First version: rendered and selectable as one object, with its source opening in place on Enter or Edit. Later: cell editing that writes only the touched cell and leaves other rows' padding alone, Tab to move, with a toggle back to source. At 460 px the table pans inside its frame, which the viewer already does.

Obsidian people ask for both: a rendered table, and a way out of the forced table editor.

checked markdown.md §5.7. web Obsidian forum, plaintext table toggle; tables exploding, IME.

Code blocks

The MarkdownCodeCard look, with the body as a plain monospace flow that pans and never wraps. ``` plus Enter also writes the closing fence, so the rest of the note never flips to code mid-typing. Ctrl+Enter or Down on the last line leaves the block. Tab inserts the indent the block already uses.

checked markdown.md §5.4. inference the fence rule.

Images

A block image is one object at the reserved 320 by 4:3 (full width in the panel), so loading never moves text. Click selects it, and a card edits alt text and path. Paste or drop goes through a consumer hook that stores the file and returns the text to insert. No resolver means alt text, as today.

checked markdown.md §5.8, §6.3. checked gap: IClipboard has text only (Seams/Pal/Clipboard.cs:8-18).

Paste and copy

Pasted text goes in verbatim, one undo step. If it was Markdown, it now renders. Rich HTML paste comes later and can be dropped. Copy writes the source slice, closing any marker the selection cut through.

checked Zed's copy-as-Markdown idea (markdown.md §10.12); IClipboard as above.

Undo

One history of source edits for the whole note, restoring exact caret and selection. Typing bursts coalesce. Paste, block changes and closing delimiters seal their own step. Toggling a task is one step.

checked TextUndoOp and TextUndoStack are public and take plain offsets and strings. Cap 512 ops.

IME

Composition is a provisional span in the active flow, with clause underlines. While it lasts: no parse, no conversion, no menus, no signal write. Commit is one undo step. The candidate window follows the caret rect.

High risk. No real IME has driven this design, and the viewer doc lists IME as not driven.

checked EditableText.ImeSession (EditableText.cs:1276-1345), InputHooks.ImeSetCaretRect, markdown.md §12. not tested

Selection across blocks

One anchor and one caret, both source offsets. Each flow paints its own part, and a short tail marks a selected paragraph break. Delete removes the source range, which merges blocks naturally, and re-emits a marker only when the cut leaves one unpaired. Dragging past the edge auto-scrolls.

checked SceneStore.SetTextEditRects, ScrollHandle.AutoScroll. The viewer clamps selection to one flow today (markdown.md §7.1). inference the painting plan.

Raw source

Ctrl+/ swaps the same surface to plain monospace at the same offset, and keeps the caret line at the same height on screen. Front matter shows dimmed and read-only there by default (owner decision 3). This replaces the side-by-side pair at narrow width.

inference trivially cheap because caret and selection are already source offsets.

In the 460 px panel

  • No toolbar. The flyout, shortcuts and footer carry everything.
  • Flyout primary row is 280 px, so it fits and clamps inside the panel.
  • Menus and cards are 260 to 300 px, flipping above the caret near the bottom.
  • Document type scale: H1 20/28 holds one line, per markdown.md §5.1.
  • Tables pan in their frame. Images fill the width up to 320.

In a wide window

  • A top command bar, in the shape of WinUI Gallery's RichEditBox page (RichEditBoxPage.xaml:60-100): style, inline marks, Insert, Source.
  • Text column capped near 660 px for reading, centred.
  • The flyout still appears: it stays closer to the pointer.
  • Everything else behaves the same, so one control serves both.

Architecture on this engine

Type names are real unless marked new. Line numbers are at the commit above.

SourceBuffer new

The file's characters including its newlines, BOM and final-newline state. The only document. Holds offsets, anchor, caret, TextUndoStack.

MarkdownParser

Exists, cold path. Gives blocks with SourceStart/SourceEnd. Gains an inline source map and front matter. Re-parses the edited block range.

Projection new

Per leaf block: display string, display-to-source map, TextSpans. A pure function of the source, independent of the caret, so moving the caret costs nothing.

Scene

SpanTextEl flow per leaf, bound through Prop<TextSpans>. TextEditState and SetTextEditRects paint caret and selection.

Keys, characters, IME and pointer enter at one focus root (the EditableText handler set), become a command, then one (start, removed, inserted) replace on the buffer.

Round-trip rules, the hardest requirement

R1Nothing is serialized. A save writes the buffer. The only way a byte changes is a replace that a command asked for.
R2A command touches its own range and nothing else. Bold writes two markers. A task toggle writes one character.
R3New syntax copies its neighbours: the sibling's bullet and number style, the note's emphasis marker. Defaults apply only when there is no neighbour.
R4Inserted newlines use the note's dominant ending. Mixed endings stay mixed. BOM and final newline are never added or removed.
R5Front matter is a protected range: rendered as a slot, no caret stops, excluded from Ctrl+A, and it survives any body edit because no edit range reaches it.
R6Syntax the parser does not model stays literal text or an island. %%comments%%, callouts and footnotes display plainly and stay intact. Display can differ from Obsidian, and the bytes cannot.
R7A marker is written only if the result still parses as that mark: markers hug non-space text, and a cut that orphans a marker re-emits it in the same edit.

No tests, per the workspace rule. Debug builds assert after each edit that the bytes outside the replace are unchanged. A corpus of untidy notes goes through a throwaway driver, as markdown.md §12 did, and the driver is not committed. inference

Decisions for the owner

  1. 1. Markers: never revealed, or revealed at the caret?
    Recommend never. Try the toggle in the mock at 460 px. If Obsidian's feel matters more than the jump rule, that changes a default and little else.
  2. 2. Reverse the 2026-11-02 choice of source + preview?
    Recommend yes, keeping raw source as the toggle. The earlier two-pane stays until phase 1 lands.
  3. 3. Front matter in the raw view: read-only or editable?
    Recommend read-only by default with an option, since the brief says an editor must never disturb it.
  4. 4. How does a single newline in a paragraph render?
    CommonMark says a space, and that is what the viewer and this design do. From forum posts, Obsidian renders a break when strict line breaks are off. Rendering breaks needs the in-paragraph newline. web
  5. 5. Is phase 1 with tables, code and images as islands acceptable?
    Recommend yes. It is what keeps phase 1 finite. Code editing follows in phase 2.
  6. 6. Accessibility: fund the UIA text pattern before calling this done?
    It is engine wide and has no home yet. Recommend deciding before phase 1 ships, since a note editor that a screen reader cannot read is a real limit.
  7. 7. Click on a link: caret and card, or open at once?
    Recommend caret and card, with Ctrl+click to follow. Some Obsidian users will expect the other.
  8. 8. Where does it ship?
    In FluentGpu.Controls beside the viewer, or as a separate package so apps without an editor do not carry it. No recommendation: this depends on the package plan.
