# Scroll v3 — delete-and-rebuild the FluentGpu scroll mechanic

Plan date: 2026-08-17. Supersedes `docs/plans/scroll-complete-rework-inventory-2026-08-17.md` §12/§14 (the inventory stays the as-built map; this is the decision + the build plan).

## 0. Context

The user's brief: **"delete all existing scroll code and come up with a new and improved scroll mechanic that just feels super nice — right now it's shit."** Feel target (inventory §0): show-my-mom smooth — two-finger on a precision touchpad, content glued to the fingers like Photos / WinUI `ScrollView` / iOS; wheel lands; flick coasts and never bricks; no blank rows on a fling; no UI hitch = scroll hitch.

Decisions taken with the user (2026-08-17):
- The ~2.6k-line uncommitted WIP (adaptive GPU governor, `PresentUnpacedDetector`, present stats, `ScrollTrace` encodings, `ops/diag` feel-summary) is **folded into the rewrite** (not landed separately).
- Scope = **the mechanic AND the authoring-API collapse** (one `ScrollController`, ScrollView-as-chrome, recipes for the six Wavee effects, dead surface deleted).
- **Approach B (render-thread "fling lease") is IN SCOPE**, not gated.
- Precision-touchpad inertia is **engine-owned** (DM without `TRANSLATION_INERTIA`; one fling model for touch / PTP / fallback).
- Memory rules honored: no legacy paths / compat shims (replace outright, delete obsolete code); every multi-part phase has an Execution section with parallel Opus subagents on disjoint files; diagnose by reading, launch the app once with purpose.

## 1. Verdict

**Why it feels bad today (root causes, with evidence — not the inventory's symptom list):**

1. **Two cadences, one resampler that can't fix them.** DM is pumped by its own absolute-deadline pacer (`Win32DirectManipulation.UpdateCore` :398-433, reached from `Win32Platform.PumpInto` :1162 via `UpdateIfDue`), stamps every content delta at *receive* time (`_pumpQpc`, :626-635 — "the digitizer runs at roughly twice this rate, so every sample carries up to half a pump interval of quantisation"), then the engine treats those per-pump deltas as *finger samples* and least-squares-fits five of them to `frameT − 12 ms` (`ScrollIntegrator.ResampleContact` :823-900; the LSQ exists because of "±12 DIP position noise at speed, the felt grind"). During CONTACT the code hands DM a `CompositionDelta = 0` (:427-430) and then adds 12 ms of engine lag on top: **doubled latency + fit noise**. Chromium/XAML pump DM once per compositor frame and use the delta as-is; XAML also lets DM predict to composition time.
2. **The physics clock is "quantized now", not the frame's target time.** `AppHost.cs:3289` feeds `QuantizedFrameSec(Stopwatch.GetTimestamp())` — a wall-clock read snapped to the last-present refresh lattice — measured after `_anim.Tick` + incremental layout + reflow (:3280-3288: sd 1.4–2.4 ms, and 24.3 % → 37.0 % velocity roughness amplification before quantization). The compositor clock (`Win32CompositorClock`) is a bare event with no timestamp. DM and physics do not share one target time.
3. **Single-writer is a comment.** 14 direct `Offset*` writers bypass `SetScrollOffset`/`ApplyScrollPosition` (audited list in §5.3 below; the inventory's list was wrong in three places). `AssertInPhaseTick` and `gate.scroll.single-writer` only see the interactive path. Consequence: bricked flings, band freezes, "offset jumps" that no trace row can attribute.
4. **Accreted state machine.** `ScrollState` carries ~20 intent columns (`Phase`, `PhaseFlags` ×5, `PendingTarget*`, `PendingRawOffset`, `TouchPanAnchorOffset`, `FlingVelocity` (dual-purpose), `FlingRetargeted/FromOffset/SnapTarget`, `ProgrammaticZeta/Omega/SettleVelocity/HalflifeMs`, `Restore*`) and the integrator (941 lines) plus ~1,500 lines of `InputDispatcher` special-case them. OS-inertia riding requires a four-detector recovery ladder (`EngageWedge`, `Suspended`, `InertiaStall`, `SilentOwner`) that exists only because inertia lives outside the engine.
5. **UI-thread work during a fling is unbudgeted** (`_images.Pump` :3345, the ≤2-pass `ReRealizeVirtuals` catch-up :3362 — only *measured*, never bounded), and the moving scroll content is always fully re-recorded (`IsDirectMovingScrollContent` blocks span reuse, `SceneRecorder.cs:1229`). A hitch here is a scroll hitch because physics is UI-thread-only.
6. **Popups get full detented travel on a touchpad** — no DM viewport, no hi-res classifier on `Win32PopupWindow` (`Win32Platform.ForwardPopupPointerWheel` :2265-2279 hard-codes the notch path); 11 `ContentSized` popup lists in Wavee inherit a 3.6–6× over-travel.

Historical field evidence supports "phase, not throughput" (bundle 20260725: zero missed deadlines yet STEADY 1–3 because the loop produced 1.5–2.6 frames per present and DropOldest discarded 61 %) — since fixed by `DisplayPhaseGate`, and it is the same class of defect as (1)/(2): **input, physics and present were never on one clock.**

**Answer to inventory §14 ("is mom-smooth C or B?"):** Both, in this order — and the user chose to commit to both. Approach B alone would not fix (1)–(4) and (6): a compositor-thread scroller fed by a jittery, doubly-lagged input stream just glides jitter more smoothly. So: **rebuild the mechanic first as a portable, POD, thread-agnostic ScrollKernel with one clock, one writer, one fling model (fixes 1–4, 6); budget the UI thread + realize-ahead (shrinks 5); then move Ballistic/Driven motion onto the render thread as a "fling lease" (finishes 5).** The kernel is designed for the lease from day one, so B is seam work, not a second rewrite. Honest ceiling (corpus law): a sustained GPU stall still shows; a hitching UI thread still stalls *new finger samples* (the message pump is the UI thread) — the lease guarantees flings/wheel-glides/snap-backs never stutter, and it extrapolates a drag only within a bounded window.

**What survives from today (structurally right):** layout-free scroll = `-offset` translation on the content child's `LocalTransform` (`layout.md §6`); the virtualization contract (`VirtualRangeDirty`, `RebaseAnchorIntents`, `IVirtualLayout`); ScrollBind eval reading post-physics offset (the *slab + eval*, not the DSL); the physics *formulas* (iOS band, WebKit spring, exact coast integral, crit-damped chase, Android IMPULSE velocity, snap math) as ~200 lines of pure functions; the async render thread + `DisplayPhaseGate` + present stats; `ops/diag` Pillar A/B instrument; the headless gate discipline.

**What is deleted:** `ScrollIntegrator.cs`, `OverscrollPhysics.cs`, `ScrollTuning.cs`, `ScrollIntoView.cs` (as a writer), the intent columns of `ScrollState`, all scroll recording/latching/wheel/touchpad/hi-res/impulse code in `InputDispatcher`, `SeedScrollFling`/holds/phase-7.6 loop in `AppHost`, `Win32DirectManipulation`'s pacer + inertia ladder, the wheel "held-notch defense", `MomentumBegin/Update/End`, `ScrollControllerAdapter`, `Repeater`, the legacy `ScrollBar.Create` overload, `ScrollChainingMode`, dead bind channels/sinks/ranges/PinKind 2/`FlagEaseInOut`/`StuckBottomBit`, ~35 integrator gates, `docs/site/api/…ScrollAnimator.yml`, plans v1/v2/v2.1 (archived).

## 2. The kernel — `src/FluentGpu.Engine/Scroll/` (namespace `FluentGpu.Scroll`, new subsystem folder)

Shape in one paragraph: `ScrollKernel` is a POD slab of `ScrollBody` (indexed by scene node index) driven by ONE `ScrollCommandPort` intake and ONE `IScrollSink` outlet. Nothing in `Scroll/` references `SceneStore`, `NodeHandle`, `RenderContext`, or delegates — that is what makes it tickable on the render thread (§6). Physics is `ScrollPhysics` (pure statics ported from `OverscrollPhysics.cs:49-220`, the chase at `ScrollIntegrator.cs:496-532`, `CoastStep` :413, `SeedFromEdgeMomentum` :457, `ScrollSnap` from `Columns.cs:526`, `ImpulseVelocity` from `InputDispatcher.cs:289-390`). UI-side glue is `SceneScrollSink` (writes `ScrollState` through a token chokepoint, content transform, binds, `VirtualRangeDirty`) and `ScrollInputRouter` (hit-test/latch/chain; converts `InputEvent` → `ScrollInput`). Chrome (`ScrollBarChrome`) is a separate UI ticker.

### 2.2 Tick semantics (per body; dt = clamp(clock.DtSec, 0, 0.034); the first tick after wake uses `RefreshSec`, never 0 — kills the zero-dt dead zone of `ScrollIntegrator.cs:349`)
- **Drag (touch/pen, ContactMove samples):** `raw = anchor + (ResampleContact(hist, FrameSec − 0.012) − x0)`; `clamped = clamp(raw)`; excess → drag-time chain (below), else `Band = BandFromExcess`. Under-sampled flick (Begin+End, ≤2 samples): End applies the final sample and seeds Ballistic from the estimator — no click (`CompleteUnderSampledPan` :2068 dies).
- **Drag (FrameDelta — DM RUNNING / hi-res fallback):** `raw += delta` 1:1 (the producer is frame-aligned by construction, §5 — no resample, no LSQ); same clamp/band split; the impulse estimator is fed `(T, Σdelta)` per frame; `ContactEnd` seeds Ballistic when `|v| ≥ FlingSeedGate` and band == 0 (else Bounce).
- **Ballistic:** `CoastStep` exact integral; snap retarget once on entry when `Frame.Snap*` set; an edge hit sets `EdgeHitPending` (velocity kept) and pins at the clamp — resolved in `Reclamp()` after layout, same frame (hole 1 below): if the fresh extent lets it move it continues; else the chain parent takes the Ballistic if it can move; else Bounce (`SeedFromEdgeMomentum`); else Idle.
- **Driven:** chase to `Target` (`ChaseStep` / underdamped); Wheel|Programmatic hard-stop at extents; retarget is velocity-continuous only when the same flavour is live (`ScrollIntoView.cs:120-123`, `InputDispatcher.cs:3810-3820`); Autoscroll = `off += v·dt`.
- **Bounce:** `StepSpring` on Band while no contact.
- **Drag-time chaining:** `ChainParent` set by the router at ContactBegin (nearest same-axis ancestor viewport). Child consumes first; leftover excess routes to the parent as `Flags|=Chained` movement in the SAME tick (parent not Parked / not at its own edge in that direction); the parent's leftover goes to the *parent's* band (outermost bands — iOS/Photos); on lift the fling seeds the body that absorbed the last non-zero delta (`LastAbsorbed`); Ballistic edge → parent (above). Policy is always Auto (`ScrollChainingMode` deleted).
- Exactly one `sink.Apply` per moved body per Tick; a body touched again in the same frame's `Reclamp` gets one more with `Writer=Reclamp`.

## 6. The render-thread fling lease (Approach B — in scope)

Concept: while a viewport is **Ballistic** (fling / bounce) or **Driven** (wheel glide / programmatic glide) with no continuous ScrollBinds, no zoom, no acrylic/video inside its content span, and the present is paced, the UI thread hands the kernel body to the render thread. The render thread self-ticks each vblank, patches the already-recorded content span, and presents — even if the UI thread published nothing (a hitch). The UI thread adopts the render-side offset at the top of each frame (≤1 frame behind for hit-test/binds/virtual), realizes ahead, and republishes with a fresh baseline. Drag never leases (finger samples arrive via the UI message pump), so a UI hitch during a drag holds position — the honest ceiling.

### 6.1 Side-table (`RenderFrame` gains a blittable `ScrollLease`; hand-back POD in `SceneFramePublisher`)

### 6.2 Render loop (`Hosting/Threading/ScrollLeaseTicker.cs`, new, pure/testable; `RenderThread.Loop` change)
The ticker holds a render-private scratch arena (pristine copy of the acquired frame's bytes + sort keys, taken once per acquire) and does `Tick(presentSec) → offset` then `Patch(dst, pristine, lease, offset)` = restore span from pristine, then `DrawList.TranslateSpan(dst, start, len, dx = −(ox−baseX)·scale, dy, motionSoft)` (make `TranslateCopiedSpan` (`DrawList.cs:732`) a static over `Span<byte>`; still rejects Acrylic → lease refused at grant time via `OpcodeStats`). **Backend prerequisite (hole found):** interior clips are pre-clamped by the recorder (`SceneRecorder.cs:1497-1500`) and rows fully outside the viewport are culled (:1541); `D3D12Device.PushScissor` (:2049) takes rects verbatim. Cost: culled-out rows recorded but scissored — flings only.

### 6.3 UI adopt / grant / continue / revoke
Top of `RunFrame` (before dispatch): read `ScrollLeaseState`; if `LeaseId` matches → the sink applies the offset with `Writer=Lease` (hit-test inverse, `VirtualRangeDirty`, overlay bar, observers all see it, ≤1 frame behind); kernel body mirror := (offset, vel), activity `LeasedOut`. Grant: on entering Ballistic/Driven and passing the eligibility test (recorder's `LeaseCaptures` for that node this frame: span offsets, `OpcodeStats` no Acrylic/Video, no continuous binds, zoom == 1, `!Unpaced`, no popup open) → publish with `Command=Grant` + `Body`. Continue: every publish while leased carries a fresh baseline = adopted offset + fresh runway (patch = renderOffset − baseline, so a stale baseline after a 100 ms hitch is still exact). Ends: (i) `Settled=1` from render → adopt final, kernel Idle, hash reset; (ii) new input for that viewport (drag/wheel), zoom, a bind appearing, node death, popup opening → UI publishes `Revoke`; the render thread patches **that** frame one last time with its current body, writes final state, stops; the UI's next frame adopts the final offset and rebases the new Drag anchor by (final − adopted) — **no backward step** (the lease always ends render-side). Body ownership: render from Grant to Revoke/settle; UI only mirrors.

### 6.4 Invariants to re-ratify (`threading-render-seam.md §1`, `§10/§11`, `§14`)
Add `ScrollLease` (UI write → render read, in the slot, release/acquire with `_publishedIdx`) and `ScrollLeaseState` (render write → UI read, seqlock) to the §1.1 table; "UI sole writer of SceneStore" holds (render never touches it; UI mirrors); "arenas render-private, UI never swaps" holds (patch a render-private scratch copy, never the slot); present-ack = last *published* seq presented — lease ticks re-present the same seq (ack monotone) and fire the present wake unconditionally; "never produce while a published frame is unpresented" becomes "the *UI* never produces…" — the render thread may present unpublished patched frames; §14: phase 2.5 (scroll physics) has a render-thread twin for leased bodies only; layout/hit-test/binds stay UI. Quarantine (`_lastConsumedSeq`) unchanged.

### 6.5 Risks → mitigations
Runway exhaustion during a hitch → clamp + hold at edge (bounded by realize-ahead; `Continue` extends). Interior clip/culling → backend intersect + expanded record. Acrylic/EdgeFade/Opacity layers → Acrylic inside span refuses lease; layers outside re-evaluate under full damage (+GPU during flings, rate-limited by `ScrollHold`). Video → refuse. Overlay scrollbar thumb ≤1 frame behind (UI-drawn) — accepted. Two writers → strict ownership + seqlock. Unpaced present (RDP) → no grants. Resize/device-lost → the lease loop polls `_wake` and honors quiesce/recover before every tick. Sub-pixel drift → restore-from-pristine each tick. Popups → no grants while a popup is open (v1). `ThreadGuard` is `[Conditional]`-erased in Ship → the lease invariants are CI-enforced by the gates below (corpus law).

## 13. Production pacing — compositor-clock model (added 2026-08-18 after the on-device runs)

### 13.1 Analysis (from two `FG_FPS_LOG` captures on the 120 Hz panel)
- Scroll frames cost 1.0–1.5 ms; the loop nevertheless produced at 88–90 fps during app load and 55–90 fps in one capture, 105–118 in another; presents came in pairs (`presentNow` alternating 0/200), i.e. two productions per one refresh window then a skipped one.
- Cause 1 (fixed 2026-08-18): `PresentUnpacedDetector` engaged on "8 sub-ms latency waits" — a condition met whenever the UI produces slower than refresh (queue never full) — floored the loop to the 15 ms software pace and could never disengage (a latch). Now requires presents landing < ½ refresh apart (impossible under vblank lock).
- Cause 2 (this section): production is paced by the **render thread's present-ack** (`DisplayPhaseGate`: arm-then-recheck on the ack seq, stall ceiling 2× refresh, `PaceAsync` wait, the §11.1.4 slip re-phase escape that re-opens on the compositor tick, `PaceSkipSubmit` special-casing, `AsyncDisplayPaceMs` wall-clock cap as fallback). The ack is one-to-two refreshes *behind* the vblank and is delivered through an auto-reset event that other producers race; the result is a phase reference that drifts, pairs and locks. The compositor clock (`Win32CompositorClock`, `DCompositionWaitForCompositorClock`) — the actual vblank — is present but **subordinate** (a supplementary wake in two branches).
- Everything downstream (kernel `FrameClock`, DM lead, the render lease) assumes one production per vblank in phase with it.

### 13.2 Model (replaces §11.1 of `threading-render-seam.md`)
1. **The compositor tick is the production clock.** `Win32CompositorClock` publishes a monotone `TickSeq` + `TickQpc` (the vblank instant) from its waiter thread; the UI reads both volatile. `AppHost` produces (Paint) at most once per tick: `PhaseGateBlocks()` ⇒ `TickSeq == _lastProducedTickSeq` (already produced for this vblank). Input/timers/posts still wake `RunFrame` immediately (dispatch/hit-test/hover latency unchanged) — only *production* is gated.
2. **Waiting:** active work (any latency-sensitive wake, kernel/chrome/anim active, producer live) ⇒ `WaitForWork` waits on the tick event (`WakeOnDisplayClock = true`) with a wall-clock backstop of 2× refresh (clamped 8–34 ms) that only fires if the clock misses. Ambient-only autonomous animation ⇒ `AmbientFrameWaitMs` (unchanged policy). HUD-only ⇒ 100 ms; idle ⇒ −1; timer clamp unchanged. Sync render path / headless ⇒ 0 (present-throttled), unchanged.
3. **No compositor clock** (probe failed: RDP/Shadow/VM, or the fast-return streak) ⇒ software pace at the refresh period (`DeriveAsyncPaceMs`) or the 60 Hz floor when the refresh is unknown; `Unpaced` for DM lead/lease refusal := `!clock.IsAvailable`. The interval-based `PresentUnpacedDetector` is deleted (the availability probe is the attestation).
4. **FrameClock:** `FrameQpc = TickQpc` of the tick that produced this frame (exact vblank; falls back to the present-stats lattice when the clock is unavailable); `PresentQpc = TickQpc + 2·refresh` (produce during interval N ⇒ Present before vblank N+1 ⇒ DWM shows at N+2 with `SetMaximumFrameLatency(1)`) — the DM lead and kernel `PresentSec` follow.
5. **Render thread:** unchanged (wake on publish, block in the frame-latency waitable, present latest, DropOldest). The present-ack **wake** (`WakePresent`/`OnRenderPresentAck`/`_presentAckEvent` phase wake) is deleted — the UI no longer sleeps on acks; `NotePresented` keeps stamping `_lastPresentQpc`/present count for `PresentFps` and the FrameClock fallback.
6. **Deleted outright:** `DisplayPhaseGate` (+ arm/recheck/ceiling escapes/`gatedFrames`), `PresentSlipDetector` + the §11.1.4 re-phase (`ShouldRephaseEscape`, `_rephase*`), `PresentUnpacedDetector`, `PaceSkipSubmit` branch (`_lastFrameSkippedSubmit` pacing), `AsyncDisplayPaceMs`/`FloorPaceMsWhenUnpaced`/`UnpacedPresentPaceMs`, `PhaseGateCeilingMs/Ticks` (folded into one `TickBackstopMs`), `HostWaitKind.{PaceAsync, PaceSkipSubmit}` → `HostWaitKind.DisplayTick` / `SoftwarePace`, `WakePresent` seam member, the `[fps]` tokens `gateD/rephD/ack/coal/lag` → `tick/prodD/dropD`; gates `gate.wake.armedSlipRephase`, `gate.wake.unpacedPresentFloor`, `gate.host.deriveAsyncPace*` (retarget), replaced by `gate.pace.one-frame-per-tick`, `gate.pace.software-fallback`, `gate.pace.ambient-cap-unchanged`, `gate.pace.input-wakes-without-producing`.
